3. **성능 및 효율성**: 로그 데이터는 매우 빠른 속도로 대량 발생하기 때문에, 불필요한 공통 컬럼을 제외하여 저장 공간을 절약하고 DB 성능을 최적화하는 것이 표준적인 설계 방식입니다.
4. **일관성**: 프로젝트 내 다른 로그성 테이블(`metric_data`, `exception_log` 등)도 동일하게 수정 관련 공통 컬럼을 생략하고 있습니다.

**USER**: 메트릭 데이터 정리 job 주기가 60분마다 보존기간7일 인데 이거 잡 설정파일은 어디 있어?

**ASSISTANT**: 이 시스템은 동적(Dynamic) 스케줄링이 가능하도록 설계되었기 때문에 `application.yml` 같은 정적 설정 파일이 아니라, **소스 코드 내 초기화 로직**과 **데이터베이스(DB)** 두 곳에서 관리됩니다.

1. **초기 기본 설정 값 (소스 코드)**: 처음 시스템이 켜져서 DB에 아무런 배치 작업이 없을 때 최초 1회 생성(Seed)하는 설정입니다. 
   - 위치: `BatchJobService.java` 파일의 `seedDefaultJobsIfEmpty()` 메서드 (약 224번째 줄)
   - 내용: `intervalMinutes(60)`, `retentionDays(7)` 등으로 하드코딩되어 있습니다.

2. **실제 동작 설정 (DB 테이블)**: 위에서 생성된 후에는 모든 설정이 DB에 저장되어 동작합니다.
   - 위치: MariaDB의 `batch_job` 테이블
   - 이유: 서버 재시작이나 소스 코드 배포를 하지 않아도 **관리자 화면(UI)**에서 주기를 30분으로 바꾸거나 보존 기간을 늘리는 등 **실시간 변경**이 가능하도록 하기 위함입니다.
   - 따라서 향후 주기를 변경하실 때는 소스를 고칠 필요 없이 관리자 화면이나 DB 데이터를 직접 수정하시면 즉시 스케줄러에 반영됩니다.
